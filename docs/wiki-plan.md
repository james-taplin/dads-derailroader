# Wiki maintenance plan

The wiki explains the application that is currently implemented. Keep product scope, setup steps, screenshots, and behavior aligned with the README and source code.

## Page groups

- Home, Installation, Your first conversion, and When a conversion stops explain the user workflow.
- Pre-build review, Simulation mapping, Placement and measurement rules, and Controls and the HUD explain generated results.
- Personal use and provenance explains the notice and source-content handling.
- Architecture, Pipeline, Testing and diagnostics, and Workflow explain repository maintenance.
- FAQ, Roadmap, Locomotive notes, and Glossary summarize supported behavior and evidence.

## Maintenance

When a user-visible message, review choice, or block changes, update its matching wiki page and `docs/resolving-blocks.md` in the same change. Use links to files and pages in `james-taplin/dads-derailroader`. Check internal links when pages move or are renamed.

Document implemented and verified behavior. Keep untested in-game behavior marked as pending.
